Effort levels: how hard the model works

/effort sets reasoning depth for the current session

The options

  • low — fast, light reasoning
  • medium — default
  • high — deeper reasoning
  • max — maximum capability, deepest reasoning
  • auto — model decides per step

How it changes behavior

  • Applies to this session only
  • Higher effort → more tokens burned
  • More tokens → more cost, faster limit hits
  • Fast mode on Opus 4.6 burns tokens hard

The more compute the tool throws at your problem, the more it costs you.

The context window is a budget

Anthropic raised Sonnet and Opus from 200k to 1M tokens — but that's the ceiling, not the target

What takes up context

  • System prompt (Anthropic's, baked in) — ~0.7%
  • System tools — ~0.7%
  • Custom agents (skills, code review, audits)
  • Memory files — CLAUDE.md, lessons, rules
  • Session-start skills loaded via hooks
  • Your messages and model responses
  • Auto-compact buffer — reserved space

The part nobody tells you

The window went 200k → 1M, but response quality starts degrading past 20–30% of the window used.

Once you cross the old 200k line, you'll see it in the outputs — repetition, dropped details, threads from unrelated parts of the session.

Pro tip: put token percent in your status line so you can see it.

/compact: clear the desk, keep the notes

Compresses the conversation to a summary, frees up the window

Basic compact

Run it when you're climbing past 20–30% used, or when you notice the model repeating or missing details.

> /compact

The model writes a summary of what you've done, keeps it in context, and drops everything else.

Compact with instructions

Tell the compactor what matters. Useful on long-running work where a naive summary drops the part you care about.

> /compact VLC streaming
  configuration and errors

That hint reshapes the summary toward your current task.

Ctrl+O opens the full conversation history — including the compaction summary the model wrote, all prior messages, and pending tasks.

Every session is saved to disk

Full transcript in JSONL — sub-agents too — on your local machine
  • Each Claude Code conversation is written out as .jsonl as you work
  • Sub-agent conversations get their own transcript files
  • There's an index file so you can point the tool at an old transcript and say "tell me about this conversation"
  • Most people don't realize this is happening
Security implication: don't paste environment secrets, tokens, or API keys into the terminal. The transcript keeps them. Treat the transcript folder the same way you'd treat a shell history file.

Memory and context work together

Two different layers, two different jobs

Context window

Short-term. Scoped to the current session. Fills up as you work, compacted or dropped when it gets full.

  • Your messages + model responses
  • Files read into the session
  • Tool results, sub-agent returns

Memory files

Long-term. Loaded every session. The persistent layer you build up for a project or beat.

  • CLAUDE.md, AGENTS.md, GEMINI.md
  • lessons.md, rules.md, memory.md
  • Skills pulled in at session start

You manage context. You build memory.

The 40% rule

Your work fills 70–80% of any context window — I'd cap it at 40%
  • One conversation per task or tight group of tasks
  • Hit 40% load — save state, compact, or start fresh
  • If you can't go from the end of one conversation to a fresh one and get the same quality, you're under-documenting — not the tool's fault
  • Save points and checkpoints: tell the model to write to CLAUDE.md as you go
The test: can a brand-new session pick up where the last one left off, with the same continuity? If yes, your project state is healthy. If no, the model was carrying things it shouldn't have been.

When to compact, clear, or quit

If you see any of these, stop adding and reset

The signs

  • Claude starts repeating itself
  • Responses miss earlier details
  • Threads from unrelated subtopics leak in
  • CLAUDE.md is referencing stale info
  • Multiple unrelated projects in one session

Your moves

  • /compact — keep this conversation, free space
  • /clear — wipe the window, reload CLAUDE.md
  • /quit — close and start a fresh session
  • Save state to CLAUDE.md before any of the above

Sub-agents: fresh context on demand

Each sub-agent gets its own 1M-token window — separate from your main conversation
  • Already used 100k tokens in the main session? Launch a sub-agent and it starts clean
  • Sub-agent runs its task, returns the result — main conversation's tokens stay intact
  • Great for: research, review, exploration, parallel analysis
  • One rule: one job per sub-agent. Scope tight, return clean

The agent-telephone problem

Errors compound when you trust sub-agent output without checking
"Something is wrong, some minutia got garbled, and the main agent has no idea that's wrong. That error gets carried into your next conversation, and the next, and it compounds." — Joe Amditis, Module 4
The fix: don't automatically trust sub-agent returns. Spot-check the result before it lands in your main conversation. The smaller the scope, the easier this is.
D2 · The 40% rule, sub-agents, and rewinding 15

Double-escape to rewind

Undo a decision, revert to a prior point in the conversation

How it works

  • Double-tap Esc
  • Menu lets you rewind all the way up the conversation
  • Pick the point you want to revert to
  • Continue from there

The catch

Once you've run /compact, you can't rewind past that compaction.

The pre-compact exchanges are gone as discrete turns — only the summary remains.

Yet another reason to keep conversations per-task, not stacked.

The scenario: second opinion before a PR

You've got a branch ready. Before you push and notify the whole team, check it against another model.
  • You're on a branch in Claude Code, about to open a PR
  • Claude Code has been giving you some rough edges this week — you want a second read
  • You don't want to formally open the PR yet — that notifies everyone watching
  • Call another CLI agent from inside your current Claude Code session
  • Get its critique, act on the findings, then open the PR

Same input, two different models, two different blind spots. Together they catch more than either one alone.

The -p flag: non-interactive mode

A one-shot prompt to an external agent — it runs, returns, exits

The pattern

From inside your Claude Code session, ask Claude to shell out to another CLI agent.

# Claude runs this as a subprocess
copilot -p "review the code on this branch"
codex -p "review this PR for issues"
gemini -p "summarize this article"

-p = non-interactive prompt. One turn, no session, done.

What you have to install

  • Copilot CLI: npm install -g @github/copilot
  • Codex CLI: npm install -g @openai/codex
  • Gemini CLI: npm install -g @google/gemini-cli

Auth inherits from existing logins — already signed into GitHub? Copilot is signed in.

D3 · Cross-model code review from the CLI 20

The sub-process stays isolated

Copilot's and Codex's analysis doesn't bloat your main context window
  • All that external analysis runs in its own process, its own context
  • Main session's token count barely moves — stayed at 6% while two reviews ran
  • Main session only absorbs the returned text — not the subprocess's internal reasoning
  • The returned review still costs tokens when it lands in your session — cheaper, not free
Cost caveat: if you're running Copilot or Codex on an API key (not a subscription), those subprocess calls still cost per-token. Subscription plan = flat rate. Know which mode you're in.

From an actual Module 4 review session

Claude Code

Your main session. Ran the feature work. Missed a loop-fix issue and a gating bug.

Flagged same-day rerun collisions, a branch that runs unconditionally, and some dead code.

How /remote-control works

Bridge a local Claude Code session to the Claude.ai web interface — and to your phone

Turn it on

  • Rename your session (/session) so it's easy to find
  • Run /remote-control — session flags as active
  • Web shows a new "Remote" session with a green status dot
  • Type in the web, it appears in your terminal — and vice versa

What it unlocks

  • Drive your local machine from the Claude.ai mobile web
  • Upload a photo from your phone — it lands in the terminal
  • Change models, add files, continue sessions on the move
  • Pair with Wake-on-LAN to keep the machine available

Anthropic-only for now. Codex and Gemini don't ship an equivalent.

Editorial judgment gets harder, not easier

A model that's right 99% of the time is more dangerous than one that's right 80%
"When anybody can produce the slop, it doesn't matter, and nothing you make is special. You have to find a way to break through that noise and differentiate yourself from everyone else who has the same access to this slop shotgun." — Joe Amditis, Module 4
The more capable the tool, the more the human-in-the-loop principle matters. Not less. Review, verify, attribute, show your work — on the code side and on the journalism side.

Four questions for picking a tool

Feature-by-feature comparisons go stale in months. These don't.
  1. What is the task? What am I trying to do, and what does a good outcome look like?
  2. How much context does this task need? What do I need to gather, clean, and provide to the tool?
  3. Do I need access to tools? Does the agent need Firecrawl, Airtable, Firebase, ytdlp, ffmpeg — and the permissions to use them?
  4. How cost-sensitive am I? What's my real-money budget, not just my token budget?

D4 · Remote control, editorial judgment, four questions 30

Q1 · What is the task?

Start concrete — what does success look like?
  • What am I actually trying to produce? A script? A summary? A data extraction?
  • What does a good outcome look like — exactly?
  • What does failure look like, and how would I spot it?
  • If I can't describe the task in a sentence, I'm not ready to pick a tool for it
D4 · Remote control, editorial judgment, four questions 31

Q2 · How much context does this task need?

Think like you're onboarding a new hire — informed, not overloaded
  • What information, sources, or institutional knowledge does the model need to do this well?
  • What's the minimum that still makes the output trustworthy?
  • Can the context travel in a CLAUDE.md, or does it need to be pulled fresh each time?
  • Too little context — generic output. Too much — noise, cost, lost focus
Same instinct you'd use bringing a new reporter onto your beat: enough to be useful, not so much they can't see what matters.
D4 · Remote control, editorial judgment, four questions 32

Q3 · Do I need access to tools?

What gear does the agent need to actually finish the job?

External tools

  • Firecrawl (scraping)
  • Airtable, Firebase, Supabase (data)
  • ytdlp, ffmpeg (media)
  • GitHub, Drive, Slack (platforms)

What you have to provide

  • Credentials and API keys
  • Scoped permissions (least privilege)
  • File-system access boundaries
  • Rate limits and budget caps
D4 · Remote control, editorial judgment, four questions 33

Q4 · How cost-sensitive am I?

Budget isn't just tokens — it's real dollars too
  • Am I willing to spend $10, $20, $100 on a one-off run?
  • Do I need to rent GPUs, pay for an API, pay for a plan?
  • What's my real-money budget, not my token budget?
  • For most journalism tasks, any of these tools will be sufficient — the question is which is best for you

Long documents, complex multi-step reasoning, or structured reliable output? Pick the tool that fits. Not the one you saw a video about.

D4 · Remote control, editorial judgment, four questions 34

Try more than one tool

Don't get loyal to a methodology — develop a feel
  • This course focused on Claude Code — but I've tried all of them
  • Each has values, gaps, and moods
  • Find your minimum viable effectiveness — what you can fall back to when something important comes up
  • It's okay to play around. You know your beat. You know your task
The goal isn't to pick the right tool forever. It's to know enough tools that you can pick the right one for this task.
