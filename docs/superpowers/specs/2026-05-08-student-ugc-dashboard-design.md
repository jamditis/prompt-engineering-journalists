# Student UGC insights dashboard — design

**Date:** 2026-05-08
**Status:** Approved (Plan 1 data pipeline already complete)
**Owner:** Joe Amditis (instructor, Knight Center "Advanced prompt engineering for journalists")

## Goal

Give the instructor (Joe) a single static dashboard he can open locally to read across the entire student cohort: who they are, what they're trying to do, what's tripping them up, and what's worth quoting. The dashboard reads the JSON files produced by the Plan 1 extraction pipeline. No backend, no API keys, no build step.

## Scope

In: eight views over already-aggregated data, render-time anonymization with a localStorage-persisted toggle, client-side search, mobile-responsive editorial-archive aesthetic.

Out: live data refresh, multi-cohort comparison, authoring/editing tools, deployment to a public URL (the corpus contains real student names — local-only).

## Audience and use cases

The reader is one person — the instructor — using this between class weeks and after the course ends to:

1. Spot the dominant themes in a forum without rereading 80 posts.
2. Find quotable passages for slides, talks, or write-ups (verbatim, with permalinks).
3. Identify struggling students or recurring confusion across modules.
4. Map the cohort by role, country, organization, and skill level.
5. Look up "did anyone mention X" via fuzzy search across all 912 posts.

## Stack

Zero-build static site. The same approach `rosen-frontend` uses elsewhere in this workspace.

- HTML + CSS + vanilla JS modules (`type="module"`).
- Library imports via `esm.sh` for the two things we don't write ourselves: MiniSearch (search), Chart.js (charts). Pinned versions, cache-busted with `?v=` params.
- Data loaded with `fetch()` from `./data/*.json` — same-origin, served by `python -m http.server`.
- No bundler, no transpiler, no package.json runtime dependencies.

Why: this matches the project's rosen-frontend convention, keeps the dashboard inspectable, and avoids tooling drift between sessions.

## Data sources

All files in `insights/dashboard/data/` (gitignored, regenerated by the pipeline):

| File | Records | Purpose |
|---|---|---|
| `overview.json` | 1 object | Cohort-wide rollups: counts, breakdowns, timeline |
| `themes.json` | 40 themes | Theme labels, descriptions, member counts, sample quote ids |
| `forums.json` | 21 forums | Per-forum top themes/tools/challenges, standout quotes |
| `students.json` | 129 students | Per-student profile + post ids + extraction snapshot |
| `quotes.json` | 531 quotes | Verbatim lines with topic, strength, permalink |
| `search-docs.json` | 912 docs | Full-text search corpus |
| `name_map.json` | 129 entries | `real_name` → `Student NNNN` |

Total payload roughly 2 MB JSON, fine to load up front for the small views and lazy-load `search-docs.json` only when the search view is opened.

## Anonymization (render-time)

Every place a real name would render, the dashboard substitutes `name_map[real_name]` first. This includes:

- `students.json[].real_name`
- `quotes.json[].author_name`
- Any `top_discussions` author fields in `overview.json`

Toggle in the header labeled "Show real names" — off by default. State persists across sessions in `localStorage` under `ugc-dashboard:show-real-names`, so a previously-set choice survives a tab close. The toggle never affects the JSON files; it switches a CSS attribute on `<body>` and a JS flag the renderers consult on every render. To reset to anonymized after enabling, the user toggles it back off.

## Aesthetic

Editorial archive — looks like a print-magazine reading room, not a SaaS dashboard.

- Background: warm off-white `#fafaf6`
- Body text: near-black `#1a1a1a`
- Accent: deep red `#a02218` (used for active nav, key numbers, quote rules — not for filling backgrounds)
- Muted: `#6b6b6b` for secondary text and metadata
- Hairline rules: `#d8d4cc`

Type:

- Headlines and section titles: serif (`"Source Serif 4"`, `Georgia` fallback). Italic for kickers.
- Body and UI: humanist sans (`"Inter"`, `system-ui` fallback).
- Numbers: tabular figures so columns align. Mono fallback for code-y bits.

Layout:

- Generous left/right margins on desktop. Single column on mobile.
- Wide character measure (≈70ch) for any prose. Numbers and tables go full width.
- No card shadows, no rounded corners on data containers, no gradient buttons. Hairlines and whitespace do the structural work.

Anti-AI-slop applied to every label, button, and section heading. Sentence case throughout. No "comprehensive", "robust", "leveraging", "transformative", "seamlessly", "rich". No "not just X but Y" headlines.

## Information architecture

Eight views, single-page-app navigation via hash routes (`#/overview`, `#/themes`, etc.). The header is a horizontal nav on desktop and a hamburger sheet on mobile.

### 1. Overview

Reading order top to bottom:

- **Cohort line:** "129 students from 35 countries posted 912 times across 4 modules between [start] and [end]." Single sentence, no decoration.
- **Numbers row:** total_posts, total_students, countries, languages — large tabular figures, hairline-separated.
- **Timeline:** posting volume per week (Chart.js sparkline-style bar chart, no fills, hairline axis).
- **Roles:** top 10 from `roles[]`, horizontal bar list.
- **Countries:** top 10 from `countries_breakdown[]`, same treatment.
- **Skill split:** beginner / intermediate / advanced as a single 100% stacked bar.
- **Languages:** five small chips with counts.
- **Sentiments:** six chips with counts (frustrated, curious, enthusiastic, reflective, skeptical, neutral).
- **Top tools:** top 10 from `top_tools[]`.
- **Top discussions:** top 10 from `top_discussions[]`, each linkable to its forum.

### 2. Themes

40 themes, sorted by `member_count` descending. Each row: label, member count (right-aligned tabular figure), and an "expand" affordance. Expanded state shows description, ai_summary (where present — many emergent themes have one, canonical themes mostly don't), and 2–3 sample quotes from `quotes.json` joined via `sample_quote_ids`. A theme card links to "Show all posts" which jumps to a filtered Search view.

### 3. People

Three sub-tabs along the top of the view: **Roles** / **Countries** / **Organizations**.

- Roles: list every distinct role from `students.json`, count, expand for the students with that role.
- Countries: same pattern with country.
- Organizations: same pattern with org.

Each row shows confidence badges (stated/inferred/unknown) as small inline tags so Joe knows what's claimed vs derived.

### 4. Skills

- Skill level distribution: 100% stacked bar plus the same numbers as cards (count, percent).
- Top tools: from `overview.top_tools`, plus a per-skill-level breakout (which tools advanced vs beginner students mention).
- Skill signals: aggregated `skill_signals[]` strings clustered by frequency — short list of the most common phrases like "uses ChatGPT for code help", "wants to move to CLI tools".

### 5. Forums

21 forums grouped by category with category headers:

- Course operations (5 forums)
- Module 1 — discussion (2)
- Module 1 — weekly exercise (1)
- Module 2 — discussion (3)
- Module 2 — weekly exercise (1)
- Module 3 — discussion (2)
- Module 3 — weekly exercise (1)
- Module 4 — discussion (2)
- Module 4 — weekly exercise (1)
- Final project (2)

Each forum card: name, post count, top 5 themes, top 5 tools, top 5 challenges, 2–3 standout quotes (joined from `quotes.json` via `standout_quote_ids`). Narrative + takeaways fields are reserved for Phase 3b — they may be empty for the first build; UI treats empty arrays as "no narrative yet" and hides those sections gracefully.

### 6. Student profiles

Two-pane layout on desktop (list left, detail right), stacked on mobile.

List shows anonymized name, post count, role, country, skill level. Filters at the top: role, country, skill level, module active. Sort by post count desc by default.

Detail panel shows everything in `students.json` for one student, plus links out to each post via `post_ids` and `permalink` (resolved by joining `post_ids` against the on-disk JSON files when available, or falling back to a placeholder note).

`profile_summary` and `evolution` may be empty (Phase 3c hasn't run yet) — UI treats those as "no profile narrative yet" and renders the structured fields without complaint.

### 7. Quote bank

531 quotes. Filters at the top:

- Strength (high / medium / both)
- Theme (drawn from distinct topics in `quotes.json`)
- Language (en / pt / es / fr / etc.)
- Sentiment (six values)
- Forum

Each quote renders as a typeset blockquote with a thin red left rule, the verbatim text, and a small attribution line: "{anonymized name} — {forum_slug} · {language}" plus a copy button that copies the verbatim line and a permalink note. Quotes are never paraphrased and never grammar-cleaned.

### 8. Search

MiniSearch over `search-docs.json`. Lazy-load the index — only fetch the file when the user opens the view. Build the index client-side once and cache it in memory.

Search input, language filter, forum filter. Results: forum + anonymized author + posted_at + 200-character snippet, with the matched terms underlined. Click goes to a "post detail" overlay that shows the full text from `search-docs.json[].text`.

## Mobile responsiveness

Single breakpoint at 720px. Below: stack everything to one column, fold the nav into a hamburger sheet, drop the two-pane Student profiles layout to list-then-detail screens (back button), reduce display-figure sizes by ~40%, keep the same fonts and color tokens. No horizontal scrolling anywhere except inside any wide tables, which get a `overflow-x: auto` wrapper.

## Performance

- All views except Search load their JSON eagerly on first navigation. Each is small enough (< 400 KB) that loading once and keeping in memory is fine.
- Search lazy-loads its 1.5 MB doc file and builds the index on view open — show a one-time "Building search index..." note for the second or two it takes.
- No images. No web fonts beyond Source Serif 4 + Inter (loaded from the local fonts directory or Google Fonts with `font-display: swap`).

## Privacy and PII

- No analytics, no telemetry, no third-party network calls beyond CDN fonts and the two esm.sh library imports.
- The `data/` directory is and stays gitignored.
- Anonymized by default. The toggle is for Joe's own viewing, not for sharing screenshots.
- A small footer line on every view: "Local archive — do not screenshot with names visible if sharing externally." A reminder, not a guarantee.

## Testing

This is a read-only renderer over fixed data, so testing is qualitative:

- Open `index.html` in Firefox and Chrome. Visit each of the eight views. Confirm no console errors and that each view renders something non-empty.
- Toggle "Show real names" on and off; confirm names flip in all three places (students view, quotes, top discussions).
- Resize the browser to ~360px wide. Confirm the layout stacks cleanly and the nav becomes a hamburger sheet.
- Click 5 random quotes; confirm the copy button copies verbatim text.
- Search for "Claude Code", "transcription", and a non-English term ("público"). Confirm hits.
- Visual review against the AI-slop checklist before declaring done.
